## Purpose

让访问各环境排位录像页的任何用户都能看见每条录像双方的初始卡组类型，按任一方类型筛选录像，并以通用 `.ydk` 格式下载双方在同一场 Match 中冻结的初始卡组。

## ADDED Requirements

### Requirement: 各环境录像列表展示双方卡组信息

现有公开 `GET /api/replays/:format` 必须（MUST）保留 `format`、`page`、`pageSize`、`total`、`replays` 及各录像已有的 `replayId`、`endedAt`、`player1Name`、`player2Name`、`size` 字段。每条实际存在的小局录像必须（MUST）新增 `duelIndex` 和按展示昵称顺序排列的两个 `players` 元素；每个元素包含 `name`、`deckTypeCode`、`deckTypeNameZh`、`deckCompleteness`、`deckDownloadUrl`。没有可信快照时后四个字段必须（MUST）为 `null`，页面显示“未知”且不提供卡组下载入口。顶层 `deckTypes` 必须（MUST）只返回请求环境的 `{code, nameZh}` 选项，按该环境固定顺序排列且包含 OTHERS，即使当前页为空也可供页面筛选；1103 当前只有 OTHERS。列表不得（MUST NOT）内嵌原始录像字节、完整卡片数组或 Base64 卡组。玩家身份与卡组的对应关系必须（MUST）准确，不能仅凭同名或任意一条小局记录猜测。

#### Scenario: 展示已记录的双方类型

- **WHEN** 一条 1103 或 1109 G2 录像所属 Match 的双方均有可信初始快照
- **THEN** 列表返回该录像的小局序号、双方与展示昵称对应的类型名称和各自的卡组下载入口，且类型来自 G1 前初始卡组

#### Scenario: 1103 暂无具名类型

- **WHEN** 一条 1103 录像的双方都有可信初始快照
- **THEN** 双方类型均显示“其他”，下载入口仍分别对应各自的初始卡组；缺失快照的玩家仍显示“未知”

#### Scenario: 一方缺少快照

- **WHEN** 一条录像仅有一方可验证的初始快照
- **THEN** 有快照一方显示实际类型并可下载，另一方显示“未知”且没有卡组下载入口；录像仍只出现一次

#### Scenario: 同一场的多条录像

- **WHEN** 一场 Match 产生 G1、G2、G3 三条录像
- **THEN** 列表将三条录像作为三条独立小局记录展示，但同一玩家在三条记录中的类型和初始卡组下载内容一致

### Requirement: 按任一方卡组类型筛选录像

`GET /api/replays/:format` 必须（MUST）接受可选的 `deckTypeCode`，其有效值仅为请求环境 `deck_types` 目录中的代码；当前 1109 可选 D01 至 D25 或 OTHERS，1103 只可选 OTHERS。未传或传空字符串表示全部类型。筛选必须（MUST）在分页前作用于任一方的初始类型，同一录像即使双方均命中也只计一次；`total` 必须（MUST）为筛选后的录像条数。`search` 与类型筛选同时提供时必须（MUST）取交集；排序和原有分页规则保持稳定。未提供类型筛选时必须（MUST）保留现有列表行为；请求环境没有的代码必须（MUST）返回 400，而不能悄悄回退到全部类型或使用其他环境的目录。

#### Scenario: 仅玩家二命中

- **WHEN** 用户筛选 D01，某条录像的玩家一为 D06、玩家二为 D01
- **THEN** 该录像出现在结果中一次，且 `total` 将其计入一次

#### Scenario: 双方都命中

- **WHEN** 用户筛选 D01，某条录像的双方均为 D01
- **THEN** 该录像只返回一次，分页总数也只增加一

#### Scenario: 与玩家搜索组合

- **WHEN** 用户同时提交玩家昵称搜索词和 `deckTypeCode=D01`
- **THEN** 只返回昵称搜索与任一方 D01 类型均命中的录像，`total` 与分页均依据交集计算

#### Scenario: 筛选其他与未知

- **WHEN** 用户筛选 OTHERS
- **THEN** 返回任一方明确分类为“其他”的录像，缺少快照而类型未知的录像不因此命中

#### Scenario: 无效类型代码

- **WHEN** 用户提交不存在的 `deckTypeCode`
- **THEN** 接口返回 400 的明确参数错误，不把它解释为无筛选

#### Scenario: 1103 筛选其他

- **WHEN** 用户在 1103 录像页筛选 OTHERS
- **THEN** 只返回任一方有可信初始卡组快照的录像；两方均未知的录像不命中，1109 的具名类型代码在 1103 请求中返回 400

### Requirement: 录像页提供双方类型与下载操作

`/leaderboards/:format` 的录像标签必须（MUST）在现有时间、对战双方、大小和 `.yrp` 下载的基础上展示双方卡组类型、环境内类型筛选控件以及双方各自的 `.ydk` 下载操作。类型选项来自请求环境的公开目录；更换类型、提交搜索或清空条件时必须（MUST）回到第一页，清空必须（MUST）同时清除搜索词和类型。页面必须（MUST）把类型与下载操作和正确玩家昵称对齐，并为 Side 未知的历史下载显示“部分卡组”提示。页面必须（MUST）区分加载中、空结果和请求失败，失败后可按当前条件重试；必须（MUST）说明在线保存的 Main、Extra、Side 将公开给所有访问者。不同环境的页面不得（MUST NOT）混入其他环境的录像、类型选项或卡组下载链接。

#### Scenario: 查看 1109 录像页

- **WHEN** 用户进入 1103 或 1109 页面中的录像标签
- **THEN** 每条录像显示双方类型与可用的双方下载入口，并保留录像下载、搜索、分页和刷新能力

#### Scenario: 切换类型与清空

- **WHEN** 用户在非第一页切换卡组类型，随后点击清空
- **THEN** 切换后从第一页显示新类型结果；清空后从第一页显示全部类型和空搜索词对应的结果

#### Scenario: 部分快照提示

- **WHEN** 某个历史卡组的 Side 未知但 Main 与 Extra 可下载
- **THEN** 页面明确标示该下载为“部分卡组”，不将空 Side 展示成原始副卡组为空

#### Scenario: 筛选后无结果或请求失败

- **WHEN** 类型筛选无匹配，或列表请求失败
- **THEN** 页面分别显示空结果或失败与重试提示，不继续展示上次查询的录像行

#### Scenario: 窄屏与用户文本

- **WHEN** 用户在窄屏查看页面，或昵称及类型名称含有 HTML 特殊字符
- **THEN** 类型与下载列仍可通过横向滚动访问，所有用户文本按文字显示而不执行标记或脚本

#### Scenario: 1103 页面

- **WHEN** 用户访问 `/leaderboards/1103` 的录像标签
- **THEN** 原有录像展示与 `.yrp` 下载保持可用，并出现“其他”类型筛选及双方初始卡组下载入口；不出现 1109 具名类型

### Requirement: 公开导出双方初始 YDK

系统必须（MUST）提供无需登录的 `GET /api/ladder/:format/matches/:matchId/deck`。`matchId` 指向一名玩家在请求环境中的有效排位 Match 视角；每位玩家使用各自的 `matchId` 下载，页面提供的双方链接必须（MUST）属于同一录像所对应的 `gameId`。成功响应必须（MUST）为 `text/plain; charset=utf-8` 附件，文件名安全且以 `.ydk` 结尾，并设置 `X-Deck-Completeness: complete` 或 `partial`。文件必须（MUST）按 `#main`、`#extra`、`!side` 顺序分段，以 UTF-8 文本和 CRLF 换行逐行写入该玩家快照中的原始十进制卡片 ID；重复卡保留重复行，不使用分类时归一后的 ID，不附加样例中的 `#pickup`、`#case`、卡背等外观字段。公开接口必须（MUST）沿用现有公开录像接口的限流边界。

#### Scenario: 下载完整在线卡组

- **WHEN** 访问者下载一名已有完整初始快照的玩家卡组
- **THEN** 返回可由兼容客户端导入的 `.ydk`，Main、Extra、Side 的卡片 ID 和重复张数均与 G1 前快照一致，完整性标头为 `complete`

#### Scenario: 从三局录像下载同一玩家卡组

- **WHEN** 访问者分别从同一 Match 的 G1、G2、G3 录像行点击同一玩家的卡组下载
- **THEN** 三次下载得到相同的初始卡组内容，G2/G3 换备不改变导出结果

#### Scenario: 历史 Side 未知

- **WHEN** 访问者下载只回填了 Main 与 Extra、Side 未知的历史卡组
- **THEN** 文件保留 `!side` 分段但不伪造卡片，文件名明确含 `partial`，完整性标头为 `partial`

#### Scenario: 下载目标不可用

- **WHEN** `matchId` 不存在、请求格式与 Match 或快照不一致、比赛已撤销或软删、或该玩家没有可信快照
- **THEN** 接口返回 404，不返回其他玩家或其他格式的卡组

#### Scenario: 排位功能关闭

- **WHEN** 排位能力关闭且访问者请求卡组下载
- **THEN** 接口返回明确的 503 不可用响应

### Requirement: 保持录像兼容与公开数据边界

现有 `GET /api/replays/:format/:replayId` 必须（MUST）继续返回原始 `.yrp` 字节，文件内容与本变更前一致。录像列表与卡组下载响应不得（MUST NOT）暴露账号 ID、PIN、IP 或密码；录像列表不得（MUST NOT）包含录像二进制或卡组内容，每次卡组下载只能包含目标 `matchId` 对应的一名玩家的已记录初始卡组。

#### Scenario: 录像字节保持一致

- **WHEN** 用户在本能力上线前后下载同一个有效 `replayId`
- **THEN** 两次 `.yrp` 的字节内容一致，可由原有 YGOPro 客户端播放

#### Scenario: 卡组接口无需凭据

- **WHEN** 未登录访问者使用录像页提供的玩家卡组链接
- **THEN** 在限流允许且快照有效时直接获得该玩家的 `.ydk`，响应不要求账号或管理员凭据，也不包含账号 ID、PIN 或 IP 地址
