## ADDED Requirements

### Requirement: 匿名普通 TCP 玩家可以接管半开旧连接

服务器必须（SHALL）允许已开局的非 AI YGOPro 房间中的匿名普通 TCP 玩家，通过相同的环境化房间标识、完全相同的昵称和与原玩家相同的来源 IP 恢复原玩家席位。只要原玩家席位仍存在，旧 TCP socket 是否已经报告关闭不得（SHALL NOT）影响重连资格；成功接管后只有最新连接可以继续控制该席位。

#### Scenario: 同 IP 新连接接管半开旧连接

- **WHEN** 已开局房间中的匿名普通 TCP 玩家旧连接尚未报告关闭，并从相同来源 IP 使用相同 `format#roomId` 和完全相同昵称建立新连接
- **THEN** 服务器将新连接恢复到原玩家席位、主动关闭旧连接，并按当前对局阶段向新连接发送恢复所需消息

#### Scenario: 正常关闭后从同 IP 重连

- **WHEN** 已开局房间中的匿名普通 TCP 玩家旧连接已经关闭，并从相同来源 IP 使用相同 `format#roomId` 和完全相同昵称建立新连接
- **THEN** 服务器将新连接恢复到原玩家席位，且房间中的玩家数量和席位不发生变化

#### Scenario: 不同 IP 不得接管匿名玩家席位

- **WHEN** 新连接使用相同 `format#roomId` 和昵称，但来源 IP 与原玩家保存的来源 IP 不同
- **THEN** 服务器不得替换原玩家 socket，并继续按当前阶段既有规则处理该连接为观战者或拒绝连接

#### Scenario: 昵称或房间身份不匹配

- **WHEN** 新连接的昵称不完全相同，或者环境与外部房间号的组合不完全相同
- **THEN** 服务器不得替换任何原玩家席位

#### Scenario: 连续同名连接最后接入者生效

- **WHEN** 多个满足同 IP、同房间和同昵称条件的普通 TCP 连接依次尝试接管同一席位
- **THEN** 服务器按连接处理顺序让最后一次成功接管的连接成为唯一活动 socket，并关闭此前关联的 socket

#### Scenario: 强认证和 WebSocket 重连保持隔离

- **WHEN** 原玩家使用强认证票据，或者新旧连接不都是普通 TCP 连接
- **THEN** 服务器不得通过匿名 TCP 按名称路径接管该席位，并保留既有 WebSocket token 重连和强认证保护行为

#### Scenario: 各已开局阶段恢复状态

- **WHEN** 符合条件的匿名普通 TCP 玩家在猜拳、选择先后手、决斗中或换备阶段重连
- **THEN** 服务器恢复其原位置、队伍、主机标志和阶段上下文，并发送该阶段继续交互所需的同步或提示消息

### Requirement: 全部玩家断线后提供有限重连宽限期

服务器必须（SHALL）在非 AI、非等待中的已开局房间全部玩家 socket 均确认关闭后保留房间和原玩家席位 90 秒。宽限期内成功恢复任一原玩家席位必须（SHALL）取消本次待清理；宽限期届满且仍无玩家连接时，服务器必须（SHALL）通过现有统一房间终结流程恰好清理一次。

#### Scenario: 双方断线后在宽限期内重连

- **WHEN** 已开局房间的全部玩家连接均关闭，并且任一符合条件的原玩家在 90 秒内重连
- **THEN** 服务器保留原房间和对局状态、取消待执行的房间清理，并恢复该玩家席位

#### Scenario: 宽限期内再次全部断线

- **WHEN** 玩家在宽限期内成功重连后再次断线，使房间重新没有已连接玩家
- **THEN** 服务器从该次全部断线开始重新计算完整的 90 秒宽限期

#### Scenario: 宽限期届满无人重连

- **WHEN** 已开局房间连续 90 秒没有任何玩家恢复连接
- **THEN** 服务器恰好一次移除房间、撤销其重连状态并执行既有清理副作用

#### Scenario: 等待、匹配和 AI 房间维持既有生命周期

- **WHEN** 等待阶段、匹配预留房间或 WindBot/AI 房间发生既有断线清理条件
- **THEN** 服务器继续执行当前的离房、中止或立即终结行为，不应用已开局普通房间的 90 秒宽限期

### Requirement: 重连判定具有可追踪性

服务器必须（SHALL）记录结构化的普通 TCP 重连判定与宽限期生命周期事件，并且不得（SHALL NOT）在这些事件中记录重连 token 或完整二进制协议载荷。

#### Scenario: 重连接管成功

- **WHEN** 普通 TCP 新连接成功接管原玩家席位
- **THEN** 日志包含房间身份、对局阶段和成功结果，足以关联新旧连接但不包含完整协议帧

#### Scenario: 重连条件未满足

- **WHEN** 同名加入因 IP、传输类型、认证类型或原席位不存在而未执行接管
- **THEN** 日志记录稳定的失败原因和房间阶段，且不记录任何 token

#### Scenario: 宽限期开始、取消或到期

- **WHEN** 房间进入宽限期、因玩家重连取消宽限期或宽限期到期
- **THEN** 日志分别记录对应事件和房间身份，使运维能够重建房间保留与清理时间线
