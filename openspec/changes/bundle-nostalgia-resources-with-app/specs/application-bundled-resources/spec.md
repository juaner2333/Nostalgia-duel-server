## Purpose

定义 1103/1109 固定怀旧资源与服务端应用作为同一个不可拆分版本进行构建、发布、验证和回滚的行为契约，确保任何部署都不会混用不同版本的代码、卡池、禁限卡表或裁定脚本。

## ADDED Requirements

### Requirement: 应用与固定资源作为单一版本发布

每个可部署应用制品必须（SHALL）包含该版本审核通过的固定卡片数据库、基础脚本、1103/1109 环境脚本、两份环境禁限卡表及资源锁。系统不得（SHALL NOT）独立发布、升级或回滚其中任一资源组成部分。

#### Scenario: 构建应用发布制品

- **WHEN** CI 或维护者从一个应用版本构建生产制品
- **THEN** 生成的制品同时包含该版本的代码和完整固定资源，且不依赖部署时选择另一资源版本

#### Scenario: 回滚已部署版本

- **WHEN** 运维将服务回滚到上一应用版本
- **THEN** 代码、数据库资源、禁限卡表、Lua 脚本和资源锁一同回滚到该应用版本所包含的状态

### Requirement: 干净检出直接使用固定资源

服务器必须（SHALL）直接从随应用检出的固定资源根目录加载资源。干净检出在安装 Node.js 依赖并提供运行环境配置后，必须（SHALL）能够启动，不得（SHALL NOT）要求预先克隆、下载、组装、发布或切换资源目录。

#### Scenario: 在 WSL 中启动源码服务

- **WHEN** 开发者在干净检出中安装依赖、创建本地环境配置并执行源码启动命令
- **THEN** 服务器直接校验并加载仓库内固定资源，不要求执行任何资源准备 shell 脚本

#### Scenario: 在无网络环境启动已构建制品

- **WHEN** 已安装依赖的应用制品在无法访问外部资源仓库或下载地址的环境中启动
- **THEN** 服务器仅使用制品内资源完成 1103/1109 卡组校验与决斗初始化

### Requirement: 发布前完整校验固定资源

系统必须（SHALL）在应用制品可发布前校验固定资源锁、基础数据库卡片集合、1103/1109 白名单集合、禁限数量、LFList 摘要、基础及环境脚本摘要、必需文件和允许的资源边界。任一组成部分缺失、漂移或越界时，构建或发布门禁必须（SHALL）失败。

#### Scenario: 完整固定资源通过校验

- **WHEN** 数据库、双环境 LFList、脚本目录和资源锁全部存在且内容摘要一致
- **THEN** 资源门禁成功，并确认基础卡池为 5120 个唯一卡片 ID、1103/1109 卡池分别为 5002/5120 个有效唯一 ID

#### Scenario: 资源与锁不一致

- **WHEN** 任一数据库、LFList 或 Lua 脚本在未更新资源锁的情况下发生变化，或者候选资源缺少必需文件
- **THEN** 资源门禁失败，且不得生成或发布可部署应用制品

#### Scenario: 候选资源包含未启用内容

- **WHEN** 候选制品包含 EDOPro、1103/1109 之外的赛制、额外卡池、外部脚本树或资源仓库缓存
- **THEN** 资源门禁失败并报告越界内容

### Requirement: 运行时资源保持不可变

运行中的服务器不得（SHALL NOT）从 Git、HTTP、私有覆盖或其他外部 source 获取决斗资源，不得（SHALL NOT）周期刷新、重新组装、切换或垃圾回收资源版本。卡池、禁限卡表与裁定脚本必须（SHALL）在整个应用进程生命周期内保持为制品所包含的版本。

#### Scenario: 上游资源在服务运行期间变化

- **WHEN** 任一历史数据或脚本上游仓库在应用启动后发生提交或发布
- **THEN** 当前进程加载的 1103/1109 卡池、禁限卡表和脚本保持不变，也不创建资源仓库缓存或候选 release

#### Scenario: 维护者调整怀旧资源

- **WHEN** 维护者有意修改固定卡池、禁限卡表或裁定脚本
- **THEN** 该修改只有在更新资源锁、通过完整校验并发布新的应用版本后才会进入运行环境

### Requirement: 资源版本接口反映应用内资源

资源版本接口必须（SHALL）报告当前应用制品实际加载的资源锁摘要、基础卡片集合摘要以及 1103/1109 卡池和 LFList 摘要，不得（SHALL NOT）报告独立资源发布 ID 或外部 source 状态。

#### Scenario: 查询资源版本

- **WHEN** 客户端查询已启动服务的资源版本接口
- **THEN** 响应中的固定资源摘要与当前应用制品包含并通过启动校验的资源一致
