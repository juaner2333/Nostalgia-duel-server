## Purpose

定义怀旧服可复现的固定卡片数据库、双环境卡池、裁定脚本和禁限卡表资源边界，保证 1103 与 1109 对局不会因无关上游更新或另一环境的资源而改变卡池和裁定。

## ADDED Requirements

### Requirement: 从固定 706 数据库派生双环境卡池

服务器必须（SHALL）以固定 `706-cards.cdb` 中 `datas` 表的有效卡片 ID 集合作为基础卡池。1103 与 1109 卡池必须（SHALL）分别等于已提交 `formats/<format>/lflist.conf` 的 `$whitelist` 集合；每个集合必须是基础集合的无重复子集。服务器不得（SHALL NOT）合并其他基础、format、预发布或自定义 `.cdb` 文件，亦不得（SHALL NOT）从 YDK、历史 LFList 或其他临时输入重新推导任一环境卡池。

#### Scenario: 加载 1109 完整卡池

- **WHEN** 服务器发布并加载 1109 资源版本
- **THEN** 1109 内存卡片集合等于固化 1109 配置的 `$whitelist`，当前基线为 5120 个有效卡片 ID，且每个 ID 仅出现一次

#### Scenario: 加载固化 1103 卡池

- **WHEN** 服务器发布并加载 1103 资源版本
- **THEN** 1103 内存卡片集合等于固化 1103 配置的 `$whitelist`，共包含 5002 个唯一、属于 706 基础集合的有效卡片 ID

#### Scenario: 使用环境卡池外卡片

- **WHEN** 玩家卡组包含不属于房间最终卡池的卡片 ID
- **THEN** 服务器以未知或不可用卡片拒绝该卡组，即使该 ID 存在于另一环境的卡池

### Requirement: format 脚本优先并回退基础脚本

服务器必须（SHALL）为每个房间构造与其环境绑定的脚本查找链：先查找 `formats/<format>/script`，未找到目标脚本时再查找固定 `base/script`；不得（SHALL NOT）查找其他环境的脚本目录。

#### Scenario: 环境提供裁定覆盖

- **WHEN** 当前房间的 format 脚本目录与 `base/script` 同时包含同一卡片脚本
- **THEN** 房间加载当前 format 版本，且不加载该卡片的 base 版本

#### Scenario: 环境未提供裁定覆盖

- **WHEN** 当前房间的 format 脚本目录不包含所请求脚本而 `base/script` 包含该脚本
- **THEN** 房间加载 base 版本

#### Scenario: 另一环境存在同名脚本

- **WHEN** 目标脚本仅存在于另一环境的脚本目录
- **THEN** 当前房间视为该脚本不可用，不得跨环境加载

### Requirement: 基础脚本和双环境覆盖脚本保持固定

服务器必须（SHALL）从经版本锁定并带完整性摘要的快照提供基础脚本、引擎初始化脚本、1103 覆盖脚本和 1109 覆盖脚本；启动或定时刷新不得（SHALL NOT）从浮动分支自动替换这些脚本。

#### Scenario: 上游脚本仓库发生更新

- **WHEN** 固定资源版本发布后，上游脚本仓库新增或修改脚本
- **THEN** 当前部署继续使用摘要相同的既有脚本，不改变 1103 或 1109 裁定

#### Scenario: 脚本摘要不匹配

- **WHEN** 候选资源中的任一锁定脚本与清单摘要不一致
- **THEN** 发布失败，服务器继续使用上一份完整有效的资源版本

### Requirement: 固化双环境白名单禁限卡表

系统必须（SHALL）将提交的 `formats/1103/lflist.conf` 与 `formats/1109/lflist.conf` 作为对应环境卡池与禁限配置的唯一事实来源。两份文件都必须包含 `$whitelist`，其中每个有效卡片 ID 必须恰好出现一次、均属于固定数据库且数量为 0–3。文件不得（SHALL NOT）依赖或由 YDK、历史 LFList 或其他外部输入校验、生成或扩大白名单。

#### Scenario: 校验固化双环境禁限卡表

- **WHEN** 对固定数据库和两份提交的 format 配置执行检查
- **THEN** 每份配置仅包含唯一且属于数据库的卡片 ID、数量为 0–3，白名单集合与 lock 摘要一致；当前 1103/1109 基线分别为 5002/5120 张卡

#### Scenario: 维护者调整单一环境配置

- **WHEN** 维护者直接修改一个 format 的 `$whitelist` 或任一卡片数量，然后更新资源 lock
- **THEN** 仅该 format 的卡池、LFList 摘要和 lock 条目变化；系统不要求同步修改任何其他资源输入文件

#### Scenario: 双环境白名单覆盖完整性

- **WHEN** 校验生成的 `formats/1103/lflist.conf` 与 `formats/1109/lflist.conf`
- **THEN** 每份文件的卡片 ID 集合分别等于其环境最终卡池，不含重复 ID，且所有数量均为 0、1、2 或 3

### Requirement: 仅发布显式启用的怀旧资源

部署资源树必须（SHALL）只包含固定 base 卡片数据库与脚本、显式启用的 `formats/1103` 和 `formats/1109` 禁限卡表与覆盖脚本，以及 YGOPro 决斗所需核心；不得（SHALL NOT）包含未启用赛制、扩展卡池或其上游仓库缓存。

#### Scenario: 组装双环境资源版本

- **WHEN** 从干净检出组装生产资源
- **THEN** 发布树可完成 1103 与 1109 的卡组校验和决斗，且不包含 Edison、HAT、JTP、MD、Tengu、World、Genesys、通用现代 OCG、预发布或自定义卡资源

#### Scenario: 无网络资源更新

- **WHEN** 服务器已部署固定资源版本并进入周期运行
- **THEN** 卡池、脚本和禁限卡表不需要网络拉取即可启动，后台刷新不会创建新的外部资源仓库或改变固定资源摘要

### Requirement: 固定资源以整体版本发布

卡片数据库、基础脚本、1103/1109 format 脚本、两份 format 禁限卡表和资源锁文件必须（SHALL）作为一个经过完整性校验的版本整体发布；任一组成部分缺失或失配时不得（SHALL NOT）切换活动版本。

#### Scenario: 候选版本不完整

- **WHEN** 候选发布缺少数据库、必要脚本、任一环境禁限卡表或锁文件
- **THEN** 资源发布中止，活动版本仍指向上一份完整版本

#### Scenario: 候选版本完整

- **WHEN** 候选发布的全部文件存在且摘要、双环境卡池与禁限卡表一致性校验通过
- **THEN** 系统原子切换到该版本，并向资源版本接口报告新的固定版本及两个环境的摘要
