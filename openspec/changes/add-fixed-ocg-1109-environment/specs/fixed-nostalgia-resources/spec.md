## Purpose

定义怀旧服可复现的固定卡片数据库、双环境卡池、裁定脚本和禁限卡表资源边界，保证 1103 与 1109 对局不会因无关上游更新或另一环境的资源而改变卡池和裁定。

## ADDED Requirements

### Requirement: 从固定 706 数据库派生双环境卡池

服务器必须（SHALL）以固定 `706-cards.cdb` 中 `datas` 表的有效卡片 ID 集合作为基础卡池。1109 卡池必须（SHALL）等于该基础集合；1103 卡池必须（SHALL）等于基础集合减去 `1103-diff (1).ydk` 与 `1103-diff (2).ydk` 中卡片 ID 的并集。服务器不得（SHALL NOT）合并其他基础、format、预发布或自定义 `.cdb` 文件。

#### Scenario: 加载 1109 完整卡池

- **WHEN** 服务器发布并加载 1109 资源版本
- **THEN** 1109 内存卡片集合与固定 `706-cards.cdb` 的 5120 个有效卡片 ID 完全一致，且每个 ID 仅出现一次

#### Scenario: 加载 1103 排除后卡池

- **WHEN** 服务器发布并加载 1103 资源版本
- **THEN** 1103 内存卡片集合等于 706 基础集合减去两个 1103 排除文件的并集，共包含 5002 个唯一有效卡片 ID

#### Scenario: 使用环境卡池外卡片

- **WHEN** 玩家卡组包含不属于房间最终卡池的卡片 ID
- **THEN** 服务器以未知或不可用卡片拒绝该卡组，即使该 ID 存在于另一环境的卡池

### Requirement: format 脚本优先并回退基础脚本

服务器必须（SHALL）为每个房间构造与其环境绑定的脚本查找链：先查找 `formats/<format>/script`，未找到目标脚本时再查找固定 `base/script`；不得（SHALL NOT）查找其他环境的脚本目录。

#### Scenario: 环境提供裁定覆盖

- **WHEN** 当前房间的 format 脚本目录与 `base/script` 同时包含同一卡片脚本
- **THEN** 房间加载当前 format 版本，且不加载该卡片的 base 版本

#### Scenario: 环境未提供裁定覆盖

- **WHEN** 当前房间的 format 脚本目录不包含所请求脚本而 `base/script` 包含该脚本
- **THEN** 房间加载 base 版本

#### Scenario: 另一环境存在同名脚本

- **WHEN** 目标脚本仅存在于另一环境的脚本目录
- **THEN** 当前房间视为该脚本不可用，不得跨环境加载

### Requirement: 基础脚本和双环境覆盖脚本保持固定

服务器必须（SHALL）从经版本锁定并带完整性摘要的快照提供基础脚本、引擎初始化脚本、1103 覆盖脚本和 1109 覆盖脚本；启动或定时刷新不得（SHALL NOT）从浮动分支自动替换这些脚本。

#### Scenario: 上游脚本仓库发生更新

- **WHEN** 固定资源版本发布后，上游脚本仓库新增或修改脚本
- **THEN** 当前部署继续使用摘要相同的既有脚本，不改变 1103 或 1109 裁定

#### Scenario: 脚本摘要不匹配

- **WHEN** 候选资源中的任一锁定脚本与清单摘要不一致
- **THEN** 发布失败，服务器继续使用上一份完整有效的资源版本

### Requirement: 确定性生成 1103 白名单禁限卡表

系统必须（SHALL）从固定 `706-cards.cdb`、`2011.03.lflist` 和两份 1103 排除 YDK 确定性生成单一 `formats/1103/lflist.conf`。生成文件必须包含 `$whitelist`，1103 最终卡池中的每个有效卡片 ID 必须恰好出现一次：禁限输入中的禁止、限制、准限制分别为 0、1、2，其余为 3；排除集中的卡不得（SHALL NOT）进入输出。

#### Scenario: 生成 1103 禁限卡表

- **WHEN** 对相同数据库、2011.03 禁限输入和两个排除文件重复执行生成
- **THEN** 两次输出逐字节一致，均包含 5002 个唯一卡片 ID，并具有相同的 YGOPro 禁限卡表哈希

#### Scenario: 1103 排除卡同时存在于限制输入

- **WHEN** 某卡片 ID 同时出现在 1103 排除集和 2011.03 禁限输入中
- **THEN** 该卡仍从 1103 白名单中排除，生成器报告该差异但不改变集合差运算结果

### Requirement: 确定性生成 1109 白名单禁限卡表

系统必须（SHALL）从固定 `706-cards.cdb` 与 `2011.09.lflist` 确定性生成单一 `formats/1109/lflist.conf`。生成文件必须包含 `$whitelist`，706 基础卡池中的每个有效卡片 ID 必须恰好出现一次：禁限输入中的禁止、限制、准限制分别为 0、1、2，其余为 3。

#### Scenario: 生成 1109 禁限卡表

- **WHEN** 对相同的 `706-cards.cdb` 和 `2011.09.lflist` 重复执行生成
- **THEN** 两次输出逐字节一致，均包含 5120 个唯一卡片 ID，并具有相同的 YGOPro 禁限卡表哈希

#### Scenario: 禁限输入中的卡不在环境卡池

- **WHEN** 任一环境的禁限输入包含该环境最终卡池中不存在的卡片 ID
- **THEN** 生成器以稳定诊断报告该 ID，但不把它写入白名单且不以其他 ID 静默替换

#### Scenario: 双环境白名单覆盖完整性

- **WHEN** 校验生成的 `formats/1103/lflist.conf` 与 `formats/1109/lflist.conf`
- **THEN** 每份文件的卡片 ID 集合分别等于其环境最终卡池，不含重复 ID，且所有数量均为 0、1、2 或 3

### Requirement: 仅发布显式启用的怀旧资源

部署资源树必须（SHALL）只包含固定 base 卡片数据库与脚本、显式启用的 `formats/1103` 和 `formats/1109` 禁限卡表与覆盖脚本，以及 YGOPro 决斗所需核心；不得（SHALL NOT）包含未启用赛制、扩展卡池或其上游仓库缓存。

#### Scenario: 组装双环境资源版本

- **WHEN** 从干净检出组装生产资源
- **THEN** 发布树可完成 1103 与 1109 的卡组校验和决斗，且不包含 Edison、HAT、JTP、MD、Tengu、World、Genesys、通用现代 OCG、预发布或自定义卡资源

#### Scenario: 无网络资源更新

- **WHEN** 服务器已部署固定资源版本并进入周期运行
- **THEN** 卡池、脚本和禁限卡表不需要网络拉取即可启动，后台刷新不会创建新的外部资源仓库或改变固定资源摘要

### Requirement: 固定资源以整体版本发布

卡片数据库、基础脚本、1103/1109 format 脚本、两份生成禁限卡表、两份 1103 排除文件、两份历史禁限输入和资源锁文件必须（SHALL）作为一个经过完整性校验的版本整体发布；任一组成部分缺失或失配时不得（SHALL NOT）切换活动版本。

#### Scenario: 候选版本不完整

- **WHEN** 候选发布缺少数据库、必要脚本、任一输入文件、任一环境禁限卡表或锁文件
- **THEN** 资源发布中止，活动版本仍指向上一份完整版本

#### Scenario: 候选版本完整

- **WHEN** 候选发布的全部文件存在且摘要、双环境卡池与禁限卡表一致性校验通过
- **THEN** 系统原子切换到该版本，并向资源版本接口报告新的固定版本及两个环境的摘要
