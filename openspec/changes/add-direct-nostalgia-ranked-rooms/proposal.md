## Why

当前排位入口依赖 HTTP 票据、轮询和“两人先匹配、后建房”的队列模型，不适合在线人数很少的单实例怀旧服。服务器需要让第一名玩家立即进入可等待的排位房，让后来的同格式玩家直接补位，同时提供按自然月重置的赛季榜和跨月份累计的历史总榜。

## What Changes

- 新增 `1103#TT` 与 `1109#TT` 排位入口：第一名合格玩家直接创建对应格式的排位房，后来的同格式玩家加入已有等待房；没有合适房间时才创建新房。
- **BREAKING**：以直接合房替代现有 HTTP 排队票据、状态轮询、定时配对与 WindBot 兜底流程；移除对应排队 API 和启动逻辑。
- **BREAKING**：为环境化房间标识增加唯一的非数字例外 `TT`。普通房仍严格使用 `format#数字房间号`，且继续保持匿名、无房间密码和不计排名。
- 排位玩家必须在 YGOPro `PlayerInfo` 中使用 `昵称$1234` 形式认证，`$` 后必须恰好为 4 位数字。昵称不存在时以昵称为唯一键自动创建 PIN 账号；昵称已存在时只接受正确 PIN。
- 在单实例内存中记录账号当前占用的排位房；同一账号在所有格式之间同时只能占用一个排位房，重复进入 `#TT` 时优先恢复原房间。
- 排位房复用现有房间状态、玩家席位与重连能力；等待阶段离房不计分，开战后的投降和断线终局进入正常比赛结算。
- PostgreSQL 复用现有 `users`、`matches` 和 `player_stats`：`matches` 保存逐场结果，`player_stats` 按 `format` 与北京时间自然月保存用户积分、胜场和负场；积分沿用现有小局净胜分，即每名玩家本场积分变化等于小局胜数减小局负数。
- 新增可扩展的格式排行榜页面与 API：每个格式同时提供可选择历史月份的月赛季榜和汇总全部月份的总榜；1103、1109 独立展示，未来格式复用同一路由和数据模型。

## Capabilities

### New Capabilities

- `nostalgia-ranked-play`: 定义格式化直接排位房、PIN 账号、单账号房间占用、重连结算、格式积分和排行榜的完整外部行为。

### Modified Capabilities

无。

## Impact

- YGOPro 加入路由与 `PlayerInfo` 解析、账号认证和自动注册。
- 排位房创建、等待房选择、房间列表索引、断线重连和统一终结流程。
- 现有 matchmaking 队列、HTTP controllers/routes、bootstrap、WindBot 兜底及其测试。
- `GameOverDomainEvent` 的稳定比赛标识与格式元数据、统计领域服务，以及对现有 `users`、`matches`、`player_stats` 实体和数据库模式的增量迁移；不新增排位专用数据表。
- 月赛季/总排行榜查询 API、`/leaderboards/:format` 页面、月份切换和格式注册表。
- 普通 1103/1109 数字房、固定资源、卡组规则和决斗协议版本不变；不新增 Redis 依赖。
