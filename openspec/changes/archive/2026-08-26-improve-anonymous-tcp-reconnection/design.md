## Context

参见 [proposal.md](./proposal.md) 的 Why。当前猜拳、选择先后手、决斗中和换备状态分别处理同名 JOIN，但共同调用按名称查找逻辑；casual 分支同时比较旧 socket 的实时 `remoteAddress` 并要求 `closed=true`。普通 TCP 和 WebSocket 共用 `ISocket` 与房间列表，若直接删除关闭判断会连带改变匿名 WebSocket 行为，也无法显式阻止跨传输接管。

玩家对象已经在连接建立和替换时缓存来源地址，但重连查找目前读取旧 socket 的地址；已关闭 socket 的地址可能不再稳定。房间替换连接时只移除旧包装器的消息/关闭回调并设置新 socket，没有主动销毁旧底层连接。断线处理则在发现全部玩家 socket 关闭时立即终结任何阶段的房间。

## Goals / Non-Goals

**Goals:**

- 只放宽同 IP 匿名普通 TCP 的半开连接接管，不放宽 IP、昵称、房间身份、认证类型或传输类型约束。
- 让连接替换成为同步、确定且无旧连接副作用的 `last join wins` 操作。
- 在普通已开局房间全部玩家确认断线后提供有上限、可取消且只清理一次的宽限期。
- 保持各状态已有同步协议，并补足能定位实际重连判定结果的结构化日志和测试。

**Non-Goals:**

- 不为普通 TCP 增加 token、账号认证、PIN、客户端协议命令或客户端改造。
- 不允许跨 IP 重连，也不保证路由器重拨、Wi-Fi/蜂窝切换后的恢复。
- 不持久化房间、socket 或宽限期；进程重启后不恢复内存对局。
- 不改变等待室离房、匹配房间、WindBot/AI 房间、WebSocket token 重连或强认证玩家策略。
- 不重写各阶段的场面同步、卡组重新提交或观战逻辑。

## Decisions

### 1. 显式区分 socket 传输类型

在共享 socket 端口上增加只读传输类型（`tcp` / `websocket`），由两个现有适配器固定提供。匿名半开接管仅在原 socket 和新 socket 都是普通 TCP 时启用；其他组合维持原行为。

选择显式端口属性，而不是在共享领域逻辑中依赖具体适配器的 `instanceof`，以保持依赖方向并让测试桩能直接表达传输类型。

备选方案：对所有 casual socket 一并移除关闭检查。该方案代码更少，但会无意改变匿名 WebSocket 按名称路径，因此不采用。

### 2. 使用玩家缓存的稳定来源 IP 判断资格

为玩家已缓存的来源地址提供只读访问，重连查找比较该稳定值与新连接地址，不再依赖已关闭旧 socket 是否仍能报告 `remoteAddress`。资格判定顺序固定为：原席位存在、昵称完全一致、非强认证、原/新传输均为 TCP、来源 IP 一致；不读取旧 socket 的 `closed` 状态。

查找结果返回玩家或稳定拒绝原因，使状态处理器能够记录 `player_not_found`、`strong_auth`、`transport_mismatch`、`ip_mismatch` 等结果，而不把日志职责注入纯领域判断。

备选方案：删除 IP 比较。它能覆盖网络切换，但超出本次确认范围并扩大匿名席位抢占面，因此不采用。继续等待 TCP keepalive 也不采用，因为内核发现半开连接的时间不可控，无法满足及时重连。

### 3. 同步替换连接并主动销毁旧 socket

房间的重连入口保持无 `await` 的同步临界区：捕获旧 socket，解除其房间消息和断线回调，主动 `destroy()` 旧底层连接，再把新 socket 绑定到原玩家，标记重连状态并发送现有 JOIN/TYPE_CHANGE/PLAYER_ENTER 初始化消息。解除关闭回调必须先于销毁，防止旧连接的 `close` 事件把已接管玩家当作离线玩家处理。

Node.js 单线程事件循环保证一次同步替换完成后才处理下一次 JOIN；连续合格连接因此自然形成 `last join wins`。第二次接管会关闭第一次的新 socket，最终只有最后连接保留房间消息监听器。若传入的 socket 已是当前 socket，则作为幂等保护直接返回或跳过销毁。

备选方案：只调用 `removeAllListeners()` 后替换。该方案保留半开底层连接和服务器数据解析器，存在资源泄漏及旧连接继续发送输入的风险，因此不采用。

### 4. 房间拥有单个幂等的重连宽限计时器

普通房间保存至多一个 90 秒计时器，并提供开始、取消和清理方法：

- 只有已开局、非 AI、非匹配中房间的玩家断线事件导致全部玩家 socket 关闭时才启动；重复关闭事件不得重置已有计时器。`isMatchmaking` 在预订后不会清除，因此已开局匹配对局需在断线处理器中显式排除（与 proposal 的“非匹配中对局”一致）。
- 玩家成功接管席位时立即取消计时器。
- 取消后若房间再次变为全部玩家断线，则启动新的完整 90 秒计时器。
- 到期回调重新检查房间未在终结且仍无已连接玩家，再调用现有统一终结流程。
- 统一终结流程无条件清除计时器，避免 timer 持有已销毁房间。

计时器归房间管理，因为“是否处于重连宽限期”是房间生命周期状态；到期动作仍通过应用层回调调用统一终结服务，领域对象不直接依赖房间列表、WindBot 清理或广播基础设施。

备选方案：用全局 `Map<roomId, timer>` 新建管理器。它会引入第二份房间生命周期索引并增加删除一致性风险，因此不采用。持久化宽限期不适用于当前全内存房间模型，也不采用。

### 5. 保留各阶段现有恢复协议

猜拳、选择先后手和换备继续发送各自的 DUEL_START、卡组计数或选择提示；决斗中继续走既有重新提交卡组后同步场面流程。各状态只调整重连资格输入、结构化判定日志以及对统一连接替换入口的调用，不新建平行同步实现。

等待阶段不属于席位恢复：断线玩家仍按既有规则离房，后续 JOIN 重新准入。观战者无论同名与否都不得触发玩家 socket 替换，除非该 JOIN 明确命中仍保留的原玩家记录及全部资格条件。

### 6. 日志记录判定结果而不是原始载荷

每次活动阶段的按名称 JOIN 记录统一字段：事件名、结果/拒绝原因、内部房间 ID、`formatId`、外部房间号、阶段、新旧 socket ID 和传输类型。宽限期记录 started、cancelled、expired。日志不记录 token，也不复制完整 `PlayerInfo`/`JoinGame`/卡组十六进制载荷。

日志本身不作为业务判断依据；它只用于验证哪个边界拒绝或接受重连。现有全帧 DEBUG 日志的生产级别与轮转策略另行处理。

## Risks / Trade-offs

- [同一 NAT 出口内可用房间号和昵称抢占席位] → 保留精确 IP、房间组合键和昵称校验；在日志中保留新旧 socket 关联，接受匿名协议缺少更强凭证的剩余风险。
- [公网 IP 变化仍无法重连] → 这是本次明确保留的安全边界；需要跨 IP 时另行评审 token 或认证方案。
- [旧 socket 销毁触发迟到的关闭处理] → 替换时先移除包装器登记的关闭回调，再销毁；用真实 TCP 测试断言房间和新席位不受旧 close 影响。
- [宽限期暂时保留 WASM/房间资源] → 固定为 90 秒且每房间仅一个计时器；到期复用统一终结清理。
- [计时器到期与重连同一时刻竞争] → 两者都在事件循环中串行执行；到期前重新检查连接状态和 `finalizing`，重连成功先执行时必须取消计时器。
- [多个状态处理器行为漂移] → 共享唯一资格判定与房间 socket 替换入口，并对四个已开局阶段分别建立回归测试。

## Migration Plan

1. 先加入失败测试，固定同 IP 半开接管、跨 IP 拒绝、旧 socket 销毁和 90 秒宽限行为。
2. 以最小改动扩展 socket 端口、稳定 IP 读取、共享资格判定和房间替换入口，再接入断线宽限。
3. 运行聚焦单元/真实 TCP 测试、完整 lint/test、固定资源校验和生产构建；使用临时 loopback 端口验证 1103 与 1109。
4. 部署时正常滚动替换镜像。该服务的房间为内存状态，重启会终止当时对局，应在无活跃对局窗口执行或先检查活跃房间。
5. 上线后通过结构化事件确认半开接管、IP 拒绝和宽限期清理数量，并执行双环境真实决斗冒烟。

无需数据库迁移或数据回填。回滚只需恢复上一镜像；回滚后会恢复“旧 socket 必须关闭”和“全部断线立即清理”的旧行为。
