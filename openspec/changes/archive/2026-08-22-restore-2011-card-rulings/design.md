## Context

变更动机参见 `proposal.md`，行为契约参见 `specs/historical-card-rulings/spec.md`。

固定资源当前包含一个来自 Fluorohydride 2026 快照的 `base/script`，1103 与 1109 的 format 脚本目录初始为空。运行时已经按 `[formats/<format>, base]` 查询脚本，因此不需要修改加载器；只要在两个 format 目录提交经过审核的覆盖脚本，现有隔离和回退机制即可生效。

ProjectIgnis `pre-errata` 使用现代 EDOPro Lua API、虚拟卡片 ID，且单个文件不保证对应 2011 最初版本。Fluorohydride 历史提交与本项目运行时 API 更接近，但部分 2014 年以前的旧语义早于其可用历史。因此实现必须以裁定差异为单位审阅，不能直接复制任一上游目录或整体回退仓库快照。

本变更实际交付范围（经实现确认）：第一批 12 张中的 11 张（`5861892` 光之支配者保持现代 base 裁定，其「无效失败不降攻」差异在引擎 QUICK_F 自动加入链机制下缺乏可行的 WASM 区分构造）与 `47355498` 王家长眠之谷，共 12 张。第二批其余 14 张卡经调查列入候选台账，由后续变更处理。

## Goals / Non-Goals

**Goals:**

- 在不改变运行时代码的前提下，通过现有 format-first 查找链恢复 12 张卡（第一批 11 张 + 王家长眠之谷）的 2011 OCG 行为。
- 为每个裁定差异建立先失败后通过的自动回归，并在两个环境验证脚本隔离和行为等价。
- 记录每张脚本的历史基线来源，将不改变旧裁定的引擎兼容修正保留在最终脚本中。
- 保持脚本集合、摘要和应用版本共同锁定，可通过整体应用版本回滚。
- 对已调查但未纳入本变更的卡片（第二批 14 张与光之支配者）在台账中记录候选状态与来源，供后续变更使用。

**Non-Goals:**

- 不修改 `base/script`、CDB 文本、卡片数值、LFList 或卡片可用数量。
- 不覆盖本次 12 张以外的禁止卡、待考证卡或纯脚本 Bug 修正；不恢复第二批 14 张卡与 `5861892` 的旧裁定。
- 不实现 2011-03-19 以前的起动效果优先权，也不改变 Master Rule 2 核心行为。
- 不建立运行时上游同步、动态裁定选择或第三套公共脚本目录。

## Decisions

### 1. 在两个 format 目录提交同一组独立脚本

每个目标 ID（本次共 12 个）分别写入：

```text
nostalgia-resources/ygopro/formats/1103/script/c<ID>.lua
nostalgia-resources/ygopro/formats/1109/script/c<ID>.lua
```

两个环境的同 ID 文件保持逐字节一致，并由自动测试检查 ID 集合与 SHA-256 一致性。这样保留既有 format 隔离，不修改现代 base，也允许未来出现真正的 1103/1109 差异时通过独立变更分叉。

考虑过把旧脚本放进 `base/script`，但这会抹去“现代基线 + 环境裁定覆盖”的边界，并让未来环境无法选择不同裁定。也考虑过新增共享历史目录，但运行时当前只允许当前 format 和 base，新目录会扩大已归档的固定资源契约。

### 2. 按勘误提交的父版本恢复语义，而不是整文件盲拷贝

实现时为每张卡建立一条来源记录，至少包含卡片 ID、2011 行为、现代变化、历史基线与采用的兼容修正。首选基线如下：

| 卡片 ID | 历史语义基线 |
| --- | --- |
| `26202165` | Fluorohydride `19405be^` |
| `50321796`, `77565204` | Fluorohydride `e6ec244^` |
| `21502796` | Fluorohydride `03fceae^` |
| `88264978` | Fluorohydride `f255e4c^` |
| `70583986` | Fluorohydride `cf8c409^` |
| `16226786` | Fluorohydride `34d1769^` |
| `25862681` | Fluorohydride `9150b7c^` |
| `96782886` | Fluorohydride `531580c^` |
| `47355498` | ProjectIgnis `pre-errata/c511002998.lua` 的旧裁定语义与 Fluorohydride `0c3fd99^` 的 legacy API 基线；审阅并保留后续不改变裁定的兼容修正 |
| `95727991`, `80168720` | Konami 旧文本与 ProjectIgnis 旧版语义，手工适配本项目 legacy YGOPro API |

`47355498` 明确采用 2011 OCG A 版语义：任何墓地除外均被禁止；会移动或直接影响墓地中其他卡的效果被无效；不取对象且只移动效果处理者自身的效果不因「王家长眠之谷」而无效；取对象效果即使选择处理者自身仍会被无效。2016 年勘误后新增的“连只移动自身也无效”不得带回 1103/1109。

第二批其余 14 张卡（`30604579`、`43586926`、`5645210`、`10248389`、`92001300`、`45894482`、`15894048` 与 7 张联合怪兽）与 `5861892` 不纳入本变更：前者的来源基线（Fluorohydride `e66eb28^`、`4aba941^`、`ad08881^`、`931c05a^`、`1121d30^`、`3680a31^`、`24f8f17^`、`a71f796^`、`122a028^`、`4716a68^`）已在台账中记录为候选；`5861892` 经实现验证，其「无效失败不降攻」的 2011 语义在引擎 QUICK_F 自动加入链机制下无法构造可区分的 WASM 场景，明确保持现代裁定。

考虑过直接复制 ProjectIgnis `pre-errata`，但其文件 ID、API 和历史版本含义均不满足本项目约束。也不选择完整检出旧版 Fluorohydride 脚本，因为那会丢失多年积累的引擎兼容修正。

### 3. 用清单、真实 WASM 行为和现有冒烟分层验证

遵循测试优先循环，先增加以下失败验证：

1. **覆盖清单测试**：断言两个 format 都包含规范列出的 12 个 `c<ID>.lua`、两个目录同名文件摘要一致、base/LFList/CDB 摘要未被测试夹具替代。
2. **聚焦 WASM 裁定测试**：复用 `koishipro-core.js` 与固定 CDB，通过小型测试驱动器构造所需场面、处理引擎选择消息并断言结果。第一批 11 张按 spec 中每个场景覆盖；「王家长眠之谷」覆盖禁止墓地除外、不取对象的自身移动例外、取对象的自身移动无效与墓地效果只影响卡组四个场景。
3. **格式隔离测试**：同一场景分别使用 1103 与 1109 的脚本查找链运行，并用带标记的临时脚本证明不会读取另一 format。
4. **现有回归**：保留 `NostalgiaWasmDuel.test.ts` 和 `smoke:duel` 对真实房间、卡组及决斗启动的覆盖。

测试驱动器只放在测试侧，不进入领域层或生产运行时。优先通过 `newCard` 构造最小局面，不为测试修改固定卡池或生产房间逻辑。若底层 wrapper 无法直接观察某个连续效果，则断言其产生的可观察消息、卡片状态或后续合法操作，而不是检查 Lua 源码字符串。

考虑过仅比较脚本哈希或静态匹配 `SetCountLimit`，但它们只能证明文件内容固定，不能证明引擎执行了目标裁定，因此只作为清单门禁而非行为验收。

### 4. 资源锁只接受已审核脚本后的机械更新

12 个脚本和测试通过后执行现有 `generate:nostalgia-lock`。评审必须确认：

- base 数据库摘要、卡片 ID 摘要和 1103/1109 LFList 内容未变化；
- 两个 format 的脚本数均由 0 变为 12，且目录摘要发生预期变化；
- lock 中没有新增外部 source、赛制或资源目录；
- 生成后的 `check:nostalgia-resources` 通过。

不手工编辑或拼接 `lock.json`，也不将上游 Git 元数据或临时仓库纳入固定资源树。

### 5. 用单一 Markdown 台账记录已修复、候选项和来源

本变更的最后一项任务创建 `docs/historical-card-rulings.md`。文档至少包含：

- **已修复脚本**：卡片 ID、卡名、适用环境、2011 行为摘要、与现代裁定的差异、format 脚本路径和验证状态；
- **后续候选脚本**：卡片 ID、卡名、疑似裁定差异、可能适用环境、尚缺证据或待决问题，并明确候选记录不代表已经纳入运行时；
- **旧裁定来源**：上游仓库、固定提交或文件路径、官方旧文本/FAQ 或同期 OCG 资料，以及 ProjectIgnis 虚拟 ID 到正式卡片 ID 的映射。

来源记录必须优先固定到具体提交或文件，不以浮动分支链接作为唯一依据。该文档是人工审阅台账，不进入固定资源 lock，也不得被运行时扫描为脚本来源。以后新增或移除裁定覆盖时必须在对应变更的最后同步更新该台账。

## Risks / Trade-offs

- [历史父版本同时包含旧引擎缺陷] → 只移植裁定差异，逐项审阅后续修正并用当前 WASM 执行行为测试。
- [OCG 与 TCG 旧文本或 FAQ 不一致] → 以 2011 OCG 日文文本和 OCG 处理为准，ProjectIgnis 只作辅助语义来源。
- [双目录复制产生漂移] → 自动校验 12 个 ID 的文件集合和逐文件摘要；未来差异必须通过显式 spec 变更放宽该约束。
- [真实 WASM 场景测试较多且消息驱动复杂] → 建立一个最小测试侧驱动器并按效果家族复用，不向生产代码引入测试接口。
- [旧脚本可以触发当年存在的循环或强力组合] → 这是怀旧环境的预期行为；仍由对应 LFList 和卡组校验限制可用数量。
- [台账与实际脚本漂移] → 将文档放在完整验证之后作为最后交付任务，并逐项核对 12 个目标 ID、来源和验证状态；未来裁定变更必须同步更新。

## Migration Plan

1. 增加覆盖清单和第一批（11 张）及王家长眠之谷裁定的失败测试，确认现代 base 在目标场景下产生不同结果。
2. 按来源记录逐张加入 1103 覆盖脚本（12 张），使 1103 聚焦测试通过。
3. 将审核后的 12 个相同脚本复制到 1109，执行目录一致性和双环境行为测试。
4. 运行现有完整测试后机械生成新资源锁，审核只有双环境脚本摘要及 lock 自身发生预期变化。
5. 执行 `npm run lint`、`npm run test`、`npm run check:nostalgia-resources`、`npm run build`，并对运行实例执行双环境 `npm run smoke:duel`。
6. 将应用代码与固定资源作为同一版本准备交付；若出现裁定或兼容回归，整体回滚到上一应用版本，不单独替换 Lua 或 lock。
7. 在全部实现和验证结果确定后编写历史裁定 Markdown 台账，逐项核对 12 张已修复脚本、后续候选和来源，再随同一版本交付。
