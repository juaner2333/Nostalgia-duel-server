## Purpose

定义 1103 与 1109 怀旧环境对已确认旧卡采用 2011 OCG 效果处理的可验证行为，使后续文本勘误和现代脚本更新不会改变固定怀旧对局的发动次数、对象、时点或表示形式。

## ADDED Requirements

### Requirement: 双环境提供固定的 2011 裁定覆盖集合

系统必须（SHALL）在 1103 与 1109 各自的 format 脚本范围内，为以下 12 个卡片 ID 提供 2011 OCG 裁定覆盖：`95727991`、`26202165`、`50321796`、`70583986`、`88264978`、`25862681`、`96782886`、`77565204`、`21502796`、`80168720`、`16226786`、`47355498`。两个环境对同一卡片必须（SHALL）表现出相同的 2011 裁定，且不得（SHALL NOT）读取另一环境的脚本。

#### Scenario: 1103 与 1109 请求已覆盖卡片

- **WHEN** 1103 或 1109 对局请求上述任一卡片的 Lua 脚本
- **THEN** 系统加载当前房间 format 内的 2011 裁定覆盖而不是现代 base 版本

#### Scenario: 两个环境含有相同卡片

- **WHEN** 同一覆盖卡片分别在 1103 与 1109 对局中进入可触发其效果的相同局面
- **THEN** 两个对局执行等价的 2011 OCG 效果处理

#### Scenario: 当前环境缺少覆盖脚本

- **WHEN** 被请求的卡片脚本不在当前 format 目录但存在于另一 format 目录
- **THEN** 系统不得读取另一 format 的脚本，并继续遵循既有的当前 format 到 base 的查找边界

### Requirement: 第一批卡片恢复 2011 的发动次数与检索限制

系统必须（SHALL）移除后续勘误对第一批卡片增加的卡名限次或检索后发动限制，并保留 2011 年原有的每张卡限次与发动成本。

#### Scenario: 弹射龟在同一回合再次发动

- **WHEN** `95727991` 的控制者在同一回合再次拥有可解放怪兽并发动其起动效果
- **THEN** 系统允许再次发动并按被解放怪兽攻击力的一半造成伤害

#### Scenario: 三眼怪检索怪兽

- **WHEN** `26202165` 从场上送入墓地并检索攻击力 1500 以下的怪兽
- **THEN** 系统不施加卡名一回合一次，且不禁止该回合发动检索到的卡或其同名卡

#### Scenario: 光枪龙连续回收场上卡片

- **WHEN** `50321796` 的控制者具备足够手牌并在同一回合多次发动效果
- **THEN** 系统允许每次丢弃任意数量手牌并以相同数量的双方场上可回手卡片为对象

#### Scenario: 同名卡分别使用软限次效果

- **WHEN** 同一回合中存在新的 `70583986`、`88264978` 或 `25862681` 实例且该实例尚未使用对应效果
- **THEN** 系统按 2011 的每张卡软一回合一次处理，不应用后续卡名硬一回合一次限制

#### Scenario: 精神脑魔发动旧效果

- **WHEN** `96782886` 支付 800 LP 并解放自身以外的念动力族怪兽
- **THEN** 系统允许其在同一回合再次满足成本时继续发动，且不允许将 `96782886` 自身作为解放成本

### Requirement: 第一批卡片恢复 2011 的对象、时点和表示形式

系统必须（SHALL）按 2011 OCG 规则处理第一批卡片后来发生变化的送墓时点、取对象方式、回收范围、表示形式及效果处理顺序。

#### Scenario: 未来融合发动

- **WHEN** `77565204` 的发动成功处理并确认一只融合怪兽
- **THEN** 系统在该次发动处理中立即从卡组送入对应融合素材，并在第二次自己的准备阶段处理融合召唤

#### Scenario: 雷光翻转

- **WHEN** `21502796` 的翻转效果发动且场上存在可破坏卡片
- **THEN** 系统在发动时选择一个对象，并在处理时依照旧裁定处理该对象及自己卡组顶端三张卡

#### Scenario: 暗之拜访处理攻击表示怪兽

- **WHEN** `80168720` 以表侧攻击表示怪兽为对象并成功处理
- **THEN** 目标变为里侧攻击表示而不是被强制改为里侧守备表示

#### Scenario: 深渊的暗杀者回收同名卡

- **WHEN** `16226786` 从手牌送入墓地且自己墓地存在另一张 `16226786`
- **THEN** 系统允许将另一张 `16226786` 作为旧翻转效果怪兽回收对象

### Requirement: 王家长眠之谷采用 2011 OCG A 版裁定

系统必须（SHALL）使 `47355498` 禁止双方除外墓地中的卡，并无效会移动或直接影响墓地中其他卡的效果。系统不得（SHALL NOT）仅因一个不取对象的效果在墓地发动且只移动其效果处理者自身而将其无效；取对象效果即使选择处理者自身，仍必须（SHALL）按旧裁定被无效。

#### Scenario: 以墓地卡作为除外手续

- **WHEN** 玩家尝试把墓地中的卡作为召唤手续、发动成本或效果处理除外
- **THEN** `47355498` 禁止该次墓地除外

#### Scenario: 黄泉青蛙只移动自身

- **WHEN** 「黄泉青蛙」在墓地发动不取对象的效果并只将自身特殊召唤
- **THEN** `47355498` 不无效该效果，效果依照其他适用条件处理

#### Scenario: 巨人斗士选择自身

- **WHEN** 「巨人斗士」在墓地发动取对象效果并选择自身作为特殊召唤对象
- **THEN** `47355498` 无效该效果

#### Scenario: 墓地发动的效果只影响卡组

- **WHEN** 一个效果在墓地发动但其处理只从卡组检索卡片且不移动或直接影响墓地中的卡
- **THEN** `47355498` 不仅因效果的发动位置在墓地而将其无效

### Requirement: 历史裁定资源可复现且不改变卡池

历史裁定覆盖必须（SHALL）随应用固定资源锁定和发布。增加覆盖不得（SHALL NOT）改变基础数据库、1103/1109 白名单、禁限数量、房间规则或 Master Rule 2 配置。

#### Scenario: 校验历史裁定资源

- **WHEN** 执行固定资源完整性检查
- **THEN** 两个 format 的覆盖脚本集合及内容摘要与资源锁一致，12 个目标卡片均存在于固定基础数据库和对应 format 白名单中

#### Scenario: 未更新资源锁而修改脚本

- **WHEN** 任一历史裁定覆盖脚本发生增删或内容变化但未重新生成资源锁
- **THEN** 固定资源完整性检查失败

#### Scenario: 比较变更前后的卡池与禁限数量

- **WHEN** 完成历史裁定覆盖并重新生成资源锁
- **THEN** 基础卡片 ID 摘要、1103/1109 卡池数量与两份 LFList 内容保持不变，仅格式脚本和资源锁对应摘要发生变化

### Requirement: 历史裁定修复记录可追溯

仓库必须（SHALL）提供 `docs/historical-card-rulings.md`，分别记录已经修复的脚本、后续可能修复的候选脚本和旧裁定来源。已修复记录必须（SHALL）与实际双环境覆盖一致；候选记录不得（SHALL NOT）被表述为已实现或自动进入运行时脚本集合。

#### Scenario: 完成本次历史裁定修复

- **WHEN** 12 个目标脚本、资源锁和全部验证均已完成
- **THEN** 文档列出每个已修复卡片的 ID、卡名、适用环境、旧裁定摘要、现代差异、脚本路径、来源和验证状态

#### Scenario: 记录尚待考证或待实现的脚本

- **WHEN** 调查发现可能需要旧裁定覆盖但尚未纳入本次实现的卡片
- **THEN** 文档在独立候选章节记录其 ID、卡名、疑似差异、适用环境、证据状态和待决问题，并明确其尚未修复

#### Scenario: 记录旧裁定来源

- **WHEN** 文档引用上游旧裁定脚本或历史资料
- **THEN** 来源包含可追溯的仓库、固定提交或文件路径，并在存在虚拟卡片 ID 时记录其与正式卡片 ID 的映射
