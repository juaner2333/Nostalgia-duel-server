## Purpose

为怀旧排位服提供无需登录、按格式隔离的浏览器页面，页面包含房间列表、录像下载、天梯排行三个 tab，使玩家可以查看实时房间、下载排位小局 `.yrp` 录像、浏览总榜与月赛季榜，并在空数据、错误或排位关闭时得到明确反馈。页面布局与交互参考 SRVPro rooms.html / replays.html / ladder.html 三个页面，但收敛为单页三 tab，页面品牌使用本服名称 Nostalgia Duel Server，不提供多语言切换。

## ADDED Requirements

### Requirement: 公开参数化三 tab 页面

服务器必须在排位开启时公开无需登录即可访问的 `GET /leaderboards/:format` 页面，页面必须（MUST）包含房间列表、录像下载、天梯排行三个 tab。当前有效页面必须（SHALL）包括 `/leaderboards/1103` 与 `/leaderboards/1109`，页面必须（MUST）显示实际格式且不得混入或回退到其他格式。页面标题与可见文案必须（MUST）使用本服名称 Nostalgia Duel Server，不得（SHALL NOT）出现 SRVPro 或其他外部服务器品牌。页面不得（SHALL NOT）提供语言切换，仅使用中文文案，且不得（MUST NOT）在页面内容或页面发起的请求参数中暴露账号 ID、`userId`、PIN、IP 地址或密码。

#### Scenario: 访问 1103 三 tab 页面

- **WHEN** 排位开启且用户访问 `/leaderboards/1103`
- **THEN** 服务器返回包含房间列表、录像下载、天梯排行三个 tab 的浏览器可用页面，且页面后续请求只查询 1103 的房间、录像与排行榜数据

#### Scenario: 页面品牌为 Nostalgia Duel Server

- **WHEN** 用户打开任一有效格式页面
- **THEN** 页面标题与可见文案显示 Nostalgia Duel Server 品牌，不出现 SRVPro 或其他外部服务器名称

#### Scenario: 无需登录访问页面

- **WHEN** 未携带账号、PIN、Cookie 或管理凭据的用户访问有效格式页面
- **THEN** 服务器正常返回页面，不要求认证，也不在页面中暴露账号 ID、`userId`、PIN、IP 或密码

#### Scenario: 访问未启用格式页面

- **WHEN** 用户访问未在固定格式注册表中启用的 `/leaderboards/:format`
- **THEN** 服务器返回明确的页面不存在响应，不回退到 1103、1109 或跨格式页面

#### Scenario: 排位关闭时访问页面

- **WHEN** `RANK_ENABLED=false` 且用户访问任一页面
- **THEN** 服务器返回明确的排位功能不可用响应，不渲染可能被误认为实时数据的空页面

#### Scenario: 切换 tab

- **WHEN** 用户在三个 tab 之间切换
- **THEN** 页面不整体刷新，每个 tab 保留各自的查询条件与结果状态，互不影响

### Requirement: 房间列表 tab 展示实时房间

房间列表 tab 必须（MUST）消费既有 `GET /api/getrooms`，只展示 `formatId` 与当前页面格式一致的房间，逐行显示房名（加入标识）、类型（排位/普通）、模式、玩家昵称与状态（等待中/对局中），并提供房间总数、对局中、在线玩家与更新时间统计；统计只计入当前格式房间。每个房间行必须（MUST）提供点击复制操作，方便用户把标识粘贴到客户端加入或观战：普通房复制完整加入标识 `format#roomId`，排位房展示其观战号并复制完整观战标识 `format#TT<观战号>`；复制后页面必须（MUST）给出成功或失败反馈。页面不得（SHALL NOT）自动轮询，必须（MUST）提供手动刷新。

#### Scenario: 展示当前格式房间

- **WHEN** 房间列表 tab 加载或手动刷新
- **THEN** 页面只列出当前格式的房间，排位房标注为排位类型并显示其观战号，普通房展示加入房号，统计行与列表范围一致

#### Scenario: 等待匹配中的排位房不外显玩家

- **WHEN** 一个排位房尚未开始对局
- **THEN** 玩家列显示「等待匹配中」而不显示等待玩家的昵称；普通房与已开打房间的玩家列正常显示当前玩家昵称

#### Scenario: 复制普通房加入标识

- **WHEN** 用户点击普通房行的复制操作
- **THEN** 浏览器复制该房间的完整加入标识 `format#roomId`，页面反馈复制成功或失败

#### Scenario: 复制排位房观战号

- **WHEN** 用户点击排位房行的复制操作
- **THEN** 浏览器复制该房间的完整观战标识 `format#TT<观战号>`，页面反馈复制成功或失败

#### Scenario: 手动刷新

- **WHEN** 用户点击房间列表 tab 的手动刷新
- **THEN** 页面重新请求房间数据并更新列表、统计与更新时间，此前不发生任何自动刷新

### Requirement: 排位房观战入口

服务器必须（SHALL）支持通过 `<format>#TT<观战号>`（例如 `1103#TT4821`）以无 PIN 方式观战对局中的排位房。有效观战号必须（MUST）命中当前格式的对应排位房，加入者一律以观战者身份准入并获得观战视角的对局内容；排位房中的观战者不得（SHALL NOT）被转为玩家，也不得（SHALL NOT）计入座位占用、匹配预留或比赛统计。等待匹配中或正在终结的排位房必须（MUST）拒绝观战并返回明确提示，提示不得（SHALL NOT）透露等待玩家昵称；无效观战号（不存在、格式不匹配或含额外分段）必须（MUST）被拒绝，且不得（SHALL NOT）创建或修改任何房间，也不得（SHALL NOT）回退到匹配或普通房加入流程。裸 `TT` 与 `<format>#TT` 的既有玩家匹配语义（需要 PIN）必须（MUST）保持不变。

#### Scenario: 观战对局中的排位房

- **WHEN** 未携带 PIN 的用户以 `1103#TT<观战号>` 加入一个对局中的 1103 排位房
- **THEN** 用户以观战者身份被准入并收到观战视角的对局内容，不占用座位，也不触发 PIN 认证或账号流程

#### Scenario: 换备期间加入观战

- **WHEN** 用户在排位房 MATCH 的换备间隙以有效观战号加入
- **THEN** 用户以观战者身份被准入，并在下一小局开始后仍保持观战者身份

#### Scenario: 观战等待匹配中的排位房

- **WHEN** 用户以有效观战号加入一个等待匹配中的排位房
- **THEN** 服务器拒绝进入并返回明确提示，不进入匹配、不占用座位，也不透露等待玩家昵称

#### Scenario: 观战者不转为玩家

- **WHEN** 排位房中的观战者发出入座、准备或开始请求
- **THEN** 服务器保持其观战者身份，不将其转为排位玩家

#### Scenario: 无效观战号

- **WHEN** 用户以不存在的观战号、与所请求格式不匹配的观战号或含额外分段的标识加入
- **THEN** 服务器明确拒绝，不创建或修改任何房间，也不回退到匹配或其他加入策略

#### Scenario: 观战不影响排位结算

- **WHEN** 观战者进入或离开一场排位 MATCH
- **THEN** 该 MATCH 的座位占用、终结结算与积分统计不受影响

### Requirement: 排位录像只读 API

服务器必须（SHALL）新增无需登录的排位录像只读 API。`GET /api/replays/:format` 必须（MUST）按结束时间倒序返回该格式排位小局录像的分页列表，每项包含录像 ID、结束时间、双方玩家昵称与文件大小，响应包含匹配总数 `total`，并支持可选 `page`、`pageSize`（默认每页 20 条）与 `search`（玩家昵称子串匹配）参数。`GET /api/replays/:format/:replayId` 必须（MUST）以附件下载返回该录像的原始 `.yrp` 字节，下载文件名包含结束时间与双方玩家昵称。列表接口不得（SHALL NOT）返回录像二进制；两个接口都不得（SHALL NOT）暴露 `userId`、IP 地址或账号字段；被判定无效（anulled）比赛的录像不得（SHALL NOT）出现在列表中。排位关闭时两个接口必须（MUST）返回明确不可用响应，未知格式与不存在的录像必须（MUST）返回明确不存在响应。

#### Scenario: 分页列出录像

- **WHEN** 用户请求 `/api/replays/1103?page=1&pageSize=20`
- **THEN** 返回该格式按结束时间倒序的第 1 至 20 条录像条目与匹配总数，响应不包含录像二进制内容

#### Scenario: 按玩家昵称搜索录像

- **WHEN** 用户携带 `search` 参数请求列表
- **THEN** 只返回任一方玩家昵称包含关键词的录像，总数与分页按匹配结果计算，搜索词中的通配符按字面处理

#### Scenario: 下载录像

- **WHEN** 用户请求某格式下存在的 `replayId`
- **THEN** 服务器返回可由 YGOPro 客户端解析的该小局 `.yrp` 字节，下载文件名包含结束时间与双方玩家昵称，且不包含路径或控制字符

#### Scenario: 录像不存在或格式不匹配

- **WHEN** 用户请求不存在的录像 ID，或录像 ID 与路径格式不符
- **THEN** 服务器返回明确的不存在响应，不返回其他格式或其他录像的二进制

#### Scenario: 无效比赛的录像不列出

- **WHEN** 一场比赛已被判定无效（anulled）
- **THEN** 该场比赛的录像不出现在列表与搜索结果中

#### Scenario: 排位关闭时录像 API 不可用

- **WHEN** `RANK_ENABLED=false` 且用户请求录像列表或下载
- **THEN** 服务器返回明确的排位功能不可用响应

### Requirement: 录像下载 tab

录像下载 tab 必须（MUST）以表格展示当前格式录像的时间、对战双方、大小与下载入口，提供上一页、下一页、页码信息（当前页/总页数/总条数）与刷新本页操作，并提供玩家搜索输入框（回车或搜索按钮触发、可清空）。下载入口必须（MUST）指向该录像的下载 API；每页固定 20 条。

#### Scenario: 浏览与翻页录像列表

- **WHEN** 用户进入录像下载 tab 或切换页码
- **THEN** 页面请求当前格式录像列表并逐行显示时间、对战双方、大小与下载链接，首页与末页时上一页/下一页分别禁用

#### Scenario: 搜索玩家录像

- **WHEN** 用户输入玩家昵称并触发搜索
- **THEN** 页面回到第 1 页展示匹配录像、匹配条数与页码信息；清空后恢复完整列表

#### Scenario: 录像空列表

- **WHEN** 当前格式暂无录像或搜索无匹配
- **THEN** 页面显示暂无录像，不伪造条目，也不展示上一笔查询数据

### Requirement: 天梯排行 tab 与排行榜查询扩展

天梯排行 tab 必须（MUST）提供总榜与月赛季榜两个视图：首次加载必须（MUST）查询北京时间当前 `YYYY-MM` 的月赛季榜，提供月份控件查询任意合法历史月份，总榜请求不得（SHALL NOT）携带赛季参数。表格必须（MUST）展示排名、玩家、总积分、总场次、胜场、败场与胜率，总场次等于胜场加败场，前三名名次必须（SHALL）高亮展示；分页每页固定 50 条。排行榜 API 必须（MUST）增量提供可选 `search`（玩家昵称子串匹配）、`page`、`pageSize` 参数与 `total` 响应字段；缺省这些参数时必须（MUST）保持既有默认响应契约不变。无搜索关键词时，页面必须（MUST）将排名位于后 30%（名次 / 玩家总数 ≥ 0.7）的玩家昵称显示为 `******`；有搜索关键词时必须（MUST）显示真实昵称。页面不得（SHALL NOT）渲染 API 返回的 `userId` 字段。

#### Scenario: 首次加载默认当前月榜

- **WHEN** 用户在任意本地时区打开有效格式页面
- **THEN** 页面按 `Asia/Shanghai` 计算当前 `YYYY-MM`，请求 `scope=season&season=<当前月份>` 并把该月份显示为当前选择

#### Scenario: 切换到历史总榜

- **WHEN** 用户在 1109 页面选择总榜
- **THEN** 页面请求 `/api/leaderboards/1109?scope=overall` 并显示跨月份汇总结果，不携带赛季参数

#### Scenario: 查询其他月份

- **WHEN** 用户选择一个合法的其他 `YYYY-MM` 月份
- **THEN** 页面请求当前格式的对应月赛季榜并显示所选月份，不回退到当前月或总榜

#### Scenario: 展示排行榜列

- **WHEN** 当前查询成功返回一个或多个排行项
- **THEN** 页面按 API 返回顺序显示排名、玩家昵称、总积分、总场次（胜场+败场）、胜场、败场与胜率，包括负积分与并列排序后的稳定名次，且前三名应用高亮样式

#### Scenario: 搜索玩家战绩

- **WHEN** 用户输入昵称关键词并触发搜索
- **THEN** 页面携带 `search` 请求、回到第 1 页，显示命中条目与匹配总数，命中玩家显示真实昵称

#### Scenario: 后段昵称打码

- **WHEN** 无搜索关键词且某排行项的名次除以玩家总数不小于 0.7
- **THEN** 该行玩家昵称显示为 `******`，排名与数值列照常显示

#### Scenario: 排行榜分页

- **WHEN** 玩家总数超过 50 且用户切换页码
- **THEN** 页面按 `page`/`pageSize` 请求并显示对应页条目、页码信息与总数，首页与末页时上一页/下一页分别禁用

#### Scenario: 快速连续切换查询条件

- **WHEN** 用户在前一次请求返回前再次切换视图、月份、搜索或页码
- **THEN** 页面最终只展示最后一次选择对应的数据，较早响应不得覆盖当前选择

### Requirement: 页面数据状态与安全渲染

三个 tab 都必须（MUST）明确区分加载中、空数据与请求失败状态；失败时必须（MUST）清除过期内容、显示可理解的失败提示并提供按当前条件重新请求的操作。所有用户数据（昵称、房名、玩家名）必须（MUST）以纯文本写入 DOM，不得（MUST NOT）被解释为 HTML。

#### Scenario: 请求失败与重试

- **WHEN** 排行榜、录像或房间 API 返回错误或网络请求失败
- **THEN** 对应 tab 清除过期内容、显示加载失败提示，并提供重试当前选择的操作

#### Scenario: 昵称包含 HTML 字符

- **WHEN** API 返回的昵称、房名或玩家名包含 `<`、`>`、`&` 或类似可组成标记的字符
- **THEN** 页面按原文本显示这些字符，不创建或执行其中的 HTML、脚本或事件处理器

#### Scenario: 空榜

- **WHEN** 当前查询成功但排行榜数组为空
- **THEN** 页面显示该格式与当前视图暂无排位记录，不伪造零分玩家，也不展示上一笔查询数据

### Requirement: 页面布局适配常见浏览器宽度

页面必须（MUST）在桌面与窄屏浏览器中保持 tab 切换、格式展示、搜索框、月份控件、分页控件与全部表格列可访问；表格必须（SHALL）支持横向滚动，窄屏不得（SHALL NOT）因表格宽度裁掉无法访问的列。

#### Scenario: 窄屏查看三个 tab

- **WHEN** 用户在宽度不超过 480 像素的视口打开有数据的页面
- **THEN** 用户能横向滚动查看每个 tab 的全部表格列，并能使用 tab 切换、搜索、分页与月份控件

### Requirement: 后续格式复用同一页面能力

页面不得（SHALL NOT）为 1103 与 1109 复制格式专用实现。以后通过固定格式注册表显式启用的新格式必须（MUST）能够复用同一路径、三 tab 页面结构与 API 参数，且各 tab 请求保持该格式隔离。

#### Scenario: 访问以后启用的格式

- **WHEN** 后端显式注册一个新固定格式且其排行榜与录像 API 已可用，用户访问 `/leaderboards/<新格式>`
- **THEN** 服务器使用同一页面能力展示该格式的三个 tab，所有请求保持该格式隔离，不需要新增格式专用页面
