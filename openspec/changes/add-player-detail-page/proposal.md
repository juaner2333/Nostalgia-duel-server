## Why

现有决斗专区能查看天梯和录像，但无法在同一页面了解一名玩家的总战绩、半年赛季表现、使用卡组及近期积分变化。新增玩家详情页，把已有排位比赛与卡组事实按玩家汇总，并区分公开最近记录和本人验证后的完整历史。

## What Changes

- 为 1103、1109 新增独立玩家详情页，沿用 Nostalgia Duel Server 深色样式和中文文案；从排行榜、录像及详情页对手的可见昵称进入，保留已有昵称打码规则。
- 支持总战绩与北京时间自然半年赛季，展示排名、积分、场次、胜负和胜率；查询、范围选择与分页可以通过不含凭据的网址恢复。
- 展示所选范围的使用卡组表，列为「卡组类型、场次、胜负、胜率、先手 / 后手次数、先手率」。按每场 Match 的 G1 统计先后手，未知记录不进入先后手次数及先手率分母。
- 总战绩与半年视图的积分曲线统一以当前环境的玩家当前总积分为终点，按所选范围的最近最多 10 场增减向前倒推，再按时间正序绘制；半年范围没有对局时隐藏曲线。按 Match 分页展示对战记录，提供对手、比分、G1 先后手、双方卡组、双方积分变化及倒推的结算后积分、卡组下载与小局录像入口。
- 查询框支持「昵称」或「昵称$密码」；无密码或密码错误时仅公开所选范围最近 10 条对战记录，使用被查询玩家的现有密码验证成功后允许分页查看该玩家在所选范围的全部历史。提交后输入框只保留昵称，凭据只经请求正文提交，不进入网址、浏览器持久存储、响应或日志。
- 复用现有比赛、先后手、卡组快照及下载数据；1103 的可信卡组沿用「其他」，缺失快照与先后手明确显示未知。暂不增加猜拳胜负、月度筛选、多语言或新的卡组分类规则。

## Capabilities

### New Capabilities

- `nostalgia-player-detail`: 定义玩家查询、总战绩与半年赛季、卡组使用及 G1 先后手统计、积分曲线、公开最近 10 条与验证后的完整历史、页面交互及下载入口。

### Modified Capabilities

- `nostalgia-ranked-leaderboard-page`: 为天梯与录像的可见玩家昵称增加详情入口，并保持昵称打码、环境隔离和原有操作。

## Impact

- 页面与 HTTP：新增 `/leaderboards/:format/player` 及玩家查询 API，修改决斗专区中的昵称链接；保持现有排行、录像、YDK 下载接口的访问契约。
- 应用与领域：在共享统计模块增加玩家详情用例、查询端口和统计规则，通过 `UserProfileRepository` 与 `UserProfile.isValidPassword` 复用现有密码验证，不引入独立账号系统。
- 数据：查询 `users`、`player_stats`、`matches`、`duels`、`match_decks`、`deck_types`、`duel_replays`；不新增业务数据表或重新采集历史数据。卡组与历史先后手的可用性依赖既有迁移、快照及回填，缺失时降级展示。
- 验证：增加领域、查询、权限及页面行为测试，覆盖两种环境、半年边界、未知数据、Match 去重与昵称保护；实现阶段运行 lint、完整测试、资源检查及构建。
- 发布：应用页面与 API 随同一版本发布；不执行生产查询、迁移、回填或部署，也不改变决斗、资源或排位结算逻辑。
