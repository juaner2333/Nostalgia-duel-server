# Plan：排位加入提示、等待态昵称脱敏与客户端提示中文化

> 状态：已确认，待实施
>
> 性质：排位体验与隐私改进，不改变鉴权、匹配、结算或协议结构

## 1. 背景与根因

当前存在三个问题：

1. 排位要求玩家名使用 `昵称$4位数字PIN`，完整字段受 `PlayerInfo` 的 20 个 UTF-16 字符槽限制。格式错误、PIN 位数错误或昵称过长导致 PIN 被截断时，服务端只记录英文异常并发送原生 `JOINERROR`，玩家看不到具体原因。
2. 排位等待房沿用普通房间的 `PLAYER_ENTER` 广播，双方加入后立即看到对手真实昵称。
3. 服务端仍有重复昵称、认证失败、换备倒计时、比分和引擎异常等英文客户端提示。

## 2. 目标行为

- 排位登录格式或认证失败时，依次发送“中文说明帧 → 原生 `JOINERROR` → graceful close”。
- 排位等待阶段：
  - 玩家始终看到自己的真实昵称；
  - 对手昵称显示为 `***`；
  - 服务端内部仍保存真实昵称。
- 双方准备且房主点击开局后，在发送 `DUEL_START` 和进入猜拳前恢复双方真实昵称。
- `/api/getrooms` 和 `/api/rooms` 在直接排位房处于 `WAITING` 时返回脱敏昵称；离开等待态后恢复。
- 服务端主动发送给 YGOPro TCP/WS 游戏客户端的固定英文提示全部改为中文。

## 3. 排位拒绝提示

增加轻量的 `JoinRejectionError`，分别携带内部错误原因与可安全展示的中文文案。统一加入处理器只展示该类型的错误；其他非法房间标识仍保持既有静默或原生拒绝语义。

固定提示如下：

| 场景 | 客户端提示 |
| --- | --- |
| 缺少 `$`、空昵称、PIN 非数字或不是 4 位、多个 `$`、完整字段超长并被截断 | `排位登录格式错误：请将玩家名填写为“昵称$4位数字PIN”，完整内容不能超过20个字符（例如：玩家$1234）。` |
| 已存在账号但 PIN 不匹配 | `排位密码错误：请输入该昵称对应的4位数字PIN。` |
| 账号被封禁 | `该排位账号已被封禁，如有疑问请联系管理员。` |
| 注册竞态或用户认证异常 | `排位账号认证失败，请稍后重试。` |
| 已占用另一个排位环境 | `你已加入 {当前环境} 排位，无法同时加入 {目标环境} 排位。` |
| 排位功能关闭 | `排位功能当前未开启。` |
| 排位资源不可用 | `排位房间暂时不可用，请稍后重试。` |

错误处理必须保证：

- 中文帧先于 `JOINERROR`；
- 使用 `close()` 刷新已排队帧，不使用可能丢帧的 `destroy()`；
- 失败不创建房间、不预留席位、不记录账号占用；
- 日志保留内部原因，不记录原始 PIN。

## 4. 排位昵称脱敏

### 4.1 游戏客户端

在 `YGOProRoom` 集中实现排位昵称展示策略：

- 仅当 `isDirectRanked === true` 且状态为 `WAITING` 时启用；
- 向玩家发送房间成员信息时，接收者本人使用真实昵称，其他已入座玩家统一使用 `***`；
- 普通 1103/1109 房间、AI 房间及非等待状态保持原行为；
- 不修改 `YGOProClient.name`，避免影响认证、重连、聊天、ocgcore、录像及统计。

开始对局时：

1. 确认房主发起、双方已准备；
2. 向所有房内客户端重新发送双方真实昵称的 `PLAYER_ENTER`；
3. 再发送 `DUEL_START` 和卡组数量；
4. 发放重连令牌并进入猜拳状态。

排位等待态禁止观战，因此正常路径下没有等待中的观战者；防御性实现仍不得向意外存在的观战者泄露真实昵称。

### 4.2 公开房间 API

保持响应字段结构不变，仅改变昵称值：

- `/api/getrooms`：直接排位房处于 `WAITING` 时，`users[].name` 返回 `***`；
- `/api/rooms`：直接排位房处于 `WAITING` 时，`players[].name` 返回 `***`；
- 玩家数量、位置、队伍和房间状态继续返回；
- 进入 RPS、选择先后手、决斗或换备阶段后恢复真实昵称。

按已确认范围，本次不调整管理 WebSocket 的实时房间广播。

## 5. 客户端固定提示中文化

只翻译服务端生成的游戏客户端提示，不修改协议标识、日志和动态用户内容。

| 原提示类别 | 中文文案 |
| --- | --- |
| 重复昵称 | `房间内已存在昵称为“{昵称}”的玩家。` |
| 用户名或密码错误 | `用户名或密码错误。` |
| 密码错误 | `密码错误。请先登录后再参加排位赛。` |
| 用户不存在 | `未找到用户。如需参加排位赛，请先在 https://evolutionygo.com/ 注册。` |
| 账号封禁 | `账号已被封禁。如有疑问，请联系管理员。` |
| `:score` 返回 | `比分：{玩家1} {比分1} - {比分2} {玩家2}` |
| 初始换备倒计时 | `你有 {分钟} 分钟提交副卡组。` |
| 换备剩余时间 | `还剩 {分钟} 分钟提交副卡组。` |
| 玩家换备超时广播 | `{昵称} 未在规定时间内提交副卡组，已断开连接。` |
| 超时玩家私聊 | `时间已到，你已被断开连接。` |
| ocgcore 异常平局 | `服务器发生错误，本局以平局结束。` |

以下内容保持不变：

- `:score` 命令本身；
- `OCG`、`MATCH`、格式编号和协议错误码；
- `#{replay_hint_part1}` 等客户端本地化占位符；
- 玩家聊天内容和管理员接口传入的动态广播；
- 内部日志、异常分类与 HTTP API 错误；
- 卡片检查管理页面。

## 6. 测试优先实施

### 6.1 排位格式与拒绝链路

先增加失败测试，覆盖：

- 无 `$`；
- 空昵称；
- 3 位、5 位、非数字 PIN；
- 多个 `$`；
- 昵称过长导致 `$PIN` 被截断；
- 刚好占满 20 个 UTF-16 槽的合法边界；
- 错误 PIN、封禁账号和认证异常。

断言中文提示、`JOINERROR`、关闭顺序以及无房间副作用。

### 6.2 昵称展示

覆盖：

- 第一名玩家看到自己的真实昵称；
- 第二名玩家看到自己真实昵称和对手 `***`；
- 第一名玩家看到新加入对手为 `***`；
- 两个玩家对象内部始终保存真实昵称；
- 普通房间仍互相显示真实昵称；
- 点击开局后真实昵称刷新发生在 `DUEL_START` 之前；
- RPS、实际决斗、录像元数据和排位统计使用真实昵称；
- 两个公开 API 在 `WAITING` 时脱敏，离开等待态后恢复。

### 6.3 中文提示

更新现有重复昵称、认证失败、换备超时和引擎异常测试，并补充比分提示断言，确保所有固定客户端文案均为预期中文。

### 6.4 排位冒烟

扩展 `scripts/smoke-ranked-duel.mjs`，对 1103、1109 分别验证：

1. 双方加入后收到的对手 `PLAYER_ENTER` 昵称为 `***`；
2. 开局后收到真实昵称刷新；
3. 正常完成猜拳、选先后手、真实 WASM 决斗、换备、2-0 结束和积分持久化。

按顺序执行：

```bash

```

`smoke:ranked` 使用运行中的本地测试实例和测试数据库；不得连接或写入生产环境。

## 8. 验收标准

- 排位格式、长度和认证错误均显示明确中文原因。
- 错误提示发送后连接正常关闭，不发生丢帧或房间副作用。
- 排位等待阶段客户端和两个公开房间 API 均不泄露真实对手昵称。
- 点击开局后双方恢复真实昵称，决斗、重连、录像和统计不受影响。
- 服务端固定游戏客户端提示不再包含英文自然语言。
- lint、完整测试、构建、固定资源校验及双环境排位冒烟全部通过。
- 不产生数据库迁移、依赖变化或 `nostalgia-resources/lock.json` 修改。

## 9. 回滚

本变更不涉及数据库和固定资源。若客户端不能通过重复 `PLAYER_ENTER` 正确恢复昵称，整体回滚昵称展示改动即可恢复现有行为；排位认证、房间占用和历史数据无需处理。
