# 历史裁定修复台账（Historical Card Rulings Ledger）

> 本文件是人工审阅台账：**不进入**固定资源锁，**不会被**运行时扫描为脚本来源。以后新增或移除裁定覆盖时，必须在对应变更的最后同步更新本台账。

### 验证方式

- **覆盖清单**（`historical-rulings/coverage.test.ts`）：1103 恰 376 个卡片脚本 + `special.lua`、1109 恰 377 + `special.lua`；同 ID 双环境逐字节一致；全部卡片在固定 base CDB 与对应白名单；6 张排除卡不在任何 format 目录、`67750322` 不在 1103；format 隔离（带标记临时脚本不跨 format 读取）。
- **全量加载**（`historical-rulings/all-scripts-load.test.ts`）：真实 ocgcore WASM 中 preload `special.lua` 后逐个 `newCard` 全部脚本，断言无脚本错误。
- **聚焦 WASM 场景**（`historical-rulings/batch1.test.ts`、`necrovalley.test.ts`、`special-patch.test.ts`）：使用固定 CDB、format-first 脚本链与真实 `koishipro-core.js` ocgcore，断言可观察消息/卡片状态。
- **预加载生产装配**：`special-patch.test.ts` 用与生产 worker 相同的装配（loader 派生的 `script/special.lua` 相对名 + `DirScriptReaderEx` 脚本链）加载 `initial_effect` 依赖 `aux.dserodcon` 的卡（如 `c11012887`），断言无脚本错误；`YGOProResourceLoader.test.ts` 断言派生名可被 reader 解析、绝对路径不可解析。绝对路径不得用于 preload：`DirScriptReaderEx` 会把候选路径剥掉前导 `/` 再相对 baseDir 拼接，绝对路径永远无法命中且 preload 静默无操作。
- **资源完整性**：`npm run check:nostalgia-resources` 通过；`npm run smoke:duel` 双环境建房、卡组校验、真实 WASM 决斗与观战通过。
